# mascot-forge v1.2 — implementation plan

- **Status:** Planned (not started)
- **Date:** 2026-06-20
- **Branch (suggested):** `feature/v1.2-invocation-and-scale`
- **Predecessor:** v1.1 generalisation (`docs/v1.1-generalisation-implementation-plan.md`) — shipped the
  asset-agnostic engine (ADR-0010). v1.2 is quality-of-life only: invocation ergonomics + a scale guard.

> **Correction carried into this plan.** The v1.2 planning prompt says the O(n²) CCL lives in
> `tools/vectorize-pixel.ps1`. It does **not**. `vectorize-pixel.ps1` is RLE + greedy vertical merge,
> O(W·H), no CCL. The connected-component labelling is in **`tools/segment-parts.ps1:98–102`** (P2),
> a pairwise adjacency union. All scale work below targets `segment-parts.ps1`.

---

## Goal

v1.2 done = the pipeline is **safe at scale and pleasant to invoke** without changing the engine.
Concretely: (1) `segment-parts.ps1` refuses to silently grind for ~minutes on an over-large flat.svg —
it fails fast with an actionable message that names the downscale prep; (2) an operator forges or
re-emits any `assets/<name>/` asset through a single dependency-free `mf.ps1` dispatcher instead of
remembering three raw `pwsh` invocations; (3) `pwsh tools/check-all.ps1` still passes byte-identically on
both DevBrain and Land Rover. No new runtime dependency, no Node CLI, no algorithm rewrite.

---

## Decisions

**D1 — Candidate A (scale guard): YES, but guard only (W4a), not the rewrite (W4b).**
The O(n²) is *real and measured*, not theoretical: `segment-parts.ps1:98–102` is a nested
`for i { for j>i }` adjacency union over `n` flat rects. `n` = rect count: DevBrain **89** (instant),
Land Rover **3540 → 48.6 s** (Spike 03 FINDINGS §"Per-step", item 4). The deferral note ("don't implement
unless a real asset hits >~3k rects") has therefore *already fired*. But 48.6 s on a once-per-asset,
human-in-the-loop step is annoying, not blocking — and Land Rover only reached 3540 because Step-0
downscales to 256²; the documented mitigation (`spikes/03-second-asset/prep-source.ps1`, nearest-neighbor,
ADR-0009 / W5) already caps `n`. So: add the cheap guard (a `-MaxRects` param that throws an actionable
error before the quadratic loop), which converts the real cliff — a native 1024² source → tens of
thousands of rects → minutes of silent grind — into an instant, fixable failure. **Skip W4b** (the
grid/sweep O(n)→ rewrite): no asset needs it that downscaling can't already fix, and a rewrite must
reproduce DevBrain's CCL output bit-for-bit (v1.1 plan W1 risk), i.e. real regression risk for zero
current benefit. Name the ceiling in a `ponytail:` comment + the upgrade path. This is exactly the
W4a-first / W4b-only-if-profiled split the v1.1 plan already prescribed (v1.1 plan §W4, line 164).

**D2 — Candidate B (CLI): YES, but a minimal pwsh dispatcher only — no Node CLI.**
v1.2's stated theme is invocation ergonomics, and the win is real: forging a new asset today means
recalling three separate `pwsh` calls (vectorize → segment → emit) plus one `npm --prefix … run emit`,
with paths scattered across repos. A single `mf.ps1 <verb> <asset>` is a legitimate, portfolio-legible
DX improvement. But it must be the *minimum* that works: a thin dispatcher over the scripts that already
exist, with conventional per-asset path defaults — **not** an asset-management layer.

**D3 — CLI runtime (C1) + install (C4): single PowerShell `mf.ps1`, run as `pwsh ./mf.ps1 …`.**
The repo root is deliberately dependency-free (README: "No npm install, no build step, no dependencies")
and has **no root `package.json`** — Node lives only under `tools/emit-react-gsap`. A Node CLI
(`commander`/`yargs`) would add a root `package.json`, a dependency, and an `npm link` packaging step to
wrap a pipeline that is already 3 pwsh scripts + 1 npm call — it breaks the dep-free-root contract for
marginal gain. A pwsh wrapper costs **zero** new deps, matches the pwsh-first house style, and dispatches
the npm React-emit step unchanged. Ponytail ladder: the shortest rung that holds is rung 6 (minimum code)
in pwsh, not a packaged Node tool. **Install (C4):** no `npm link`, no `npx` — invoke `pwsh ./mf.ps1 …`
from repo root (optionally a one-line `mf.cmd` shim later; deferred). **Scope (C2):** the ADR-0002
human-review pause after P2 means `forge` cannot run end-to-end unattended — `mf forge` therefore runs
P1→P2 and **stops**, printing the review/author/next-step instructions. **Asset convention (C3):**
`mf` assumes `assets/<name>/parts-spec.json` exists (both DevBrain and Land Rover already have one);
source PNG, rig, and out-dir are params with conventional defaults, **not** a registry the CLI owns.
**check-all (C5):** stays as-is; `mf check` is a one-line alias to it.

**D4 — v1.2 scope is exactly D1 (guard) + D2 (mf dispatcher) + docs.** Everything else is out (see below).

## Work items (ordered)

### W1 — Scale guard in `segment-parts.ps1` (Candidate A / W4a)
- **What:** Add a `[int]$MaxRects = 8000` param. After the flat rects are parsed (`$n = $rects.Count`,
  line 84) and **before** the O(n²) union loop (line 98), throw via `Fail` when `$n -gt $MaxRects` with an
  actionable message: the rect count, the cap, and "downscale the source with
  `spikes/03-second-asset/prep-source.ps1` (nearest-neighbor) before vectorizing — see ADR-0009 / W5".
- Default **8000** sits comfortably above Land Rover's 3540 (so re-segmenting it still works) and well
  below a native-resolution blow-up (tens of thousands → minutes).
- Update the existing comment at line 87 to a `ponytail:` ceiling note naming the upgrade path:
  `# ponytail: O(n^2) pairwise union; guarded by -MaxRects. Replace with a grid/sweep (W4b) only if a
  non-downscalable asset needs >8000 rects.`
- Optionally print elapsed segmentation time on success (one `Stopwatch`) so the cliff is visible before
  it's hit. (Nice-to-have; cut if it complicates determinism — it must not change SVG/HTML output.)
- **Acceptance:** DevBrain (89) and Land Rover (3540) segment unchanged; a synthetic flat.svg with
  `>8000` rects fails instantly with the named message, not a multi-minute hang.
- **Gate:**
  ```powershell
  # DevBrain unchanged (byte-identical):
  $tmp = "$env:TEMP\devbrain-seg-w1.svg"
  pwsh tools/segment-parts.ps1 -Flat docs/buildable-slice/devbrain-flat.svg `
    -Spec assets/devbrain/parts-spec.json -Out $tmp
  git diff --no-index docs/buildable-slice/devbrain-segmented.svg $tmp   # must exit 0
  ```

### W2 — `mf.ps1` dispatcher scaffold (Candidate B / C1, C4)
- **What:** `tools/mf.ps1` (or repo-root `mf.ps1`) — a `param([string]$Verb, [string]$Asset, ...passthru)`
  dispatcher with a `switch` on `$Verb`. No new deps. Resolve `$repoRoot` the same way the other tools do.
  Unknown verb → print usage + non-zero exit.
- **Acceptance:** `pwsh ./mf.ps1` with no/unknown verb prints `forge | emit | check` usage and exits 1.
- **Gate:** `pwsh ./mf.ps1 bogus; if ($LASTEXITCODE -eq 0) { throw }` (non-zero on bad verb).

### W3 — `mf forge <asset>` (P1→P2, stops at the human pause) (C2, C3)
- **What:** Runs `vectorize-pixel.ps1` then `segment-parts.ps1` for `assets/<asset>/`, then **stops** and
  prints: open `<asset>-segmented-review.html`, author/confirm `<asset>-rigged.json`, then run
  `mf emit <asset>`. Conventional defaults: `-Spec assets/<asset>/parts-spec.json`; source/out paths
  derived from `<asset>` with overridable params. Pass `-MaxRects` through to W1.
- **Acceptance:** `pwsh ./mf.ps1 forge devbrain` reproduces the current two-step output into the expected
  paths and prints the review/next-step block; it does **not** run P3.
- **Gate:** run it, diff the produced flat/segmented SVGs against the committed DevBrain goldens — no change.

### W4 — `mf emit <asset>` (P3 both targets) (C2)
- **What:** Runs `emit-svg-css.ps1 -AssetName <asset> …` and `npm --prefix tools/emit-react-gsap run emit`
  (with `RIG_PATH`/`SVG_PATH` env pointed at `<asset>`), the post-review half of the pipeline.
- **Acceptance:** `pwsh ./mf.ps1 emit devbrain` produces byte-identical output to the two raw calls it wraps.
- **Gate:**
  ```powershell
  pwsh ./mf.ps1 emit devbrain
  git diff docs/buildable-slice/generated/        # must show nothing
  ```

### W5 — `mf check` alias (C5)
- **What:** `mf check` → `& pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-all.ps1`, passing
  through the exit code. `check-all.ps1` is unchanged.
- **Acceptance:** `pwsh ./mf.ps1 check` and `pwsh tools/check-all.ps1` produce identical summary + exit code.
- **Gate:** `pwsh ./mf.ps1 check; $a=$LASTEXITCODE; pwsh tools/check-all.ps1; if ($LASTEXITCODE -ne $a) { throw }`

### W6 — Docs (README + tool headers)
- **What:** README "Run / Quickstart" gains a **"Forge a new asset"** block showing `mf forge <name>` →
  review → `mf emit <name>` → `mf check`, replacing the implicit raw-pwsh-only path. Note the `-MaxRects`
  guard + the prep-source downscale for oversized inputs. Add a one-line header note to `segment-parts.ps1`
  (guard) and `mf.ps1` (purpose, dep-free, dispatches existing scripts).
- **Acceptance:** README quickstart runs as written for `devbrain`; no stale "raw 3-call" instructions left
  as the only path.

### W7 — Regression gate (always last)
- **Acceptance:** `pwsh tools/check-all.ps1` exits 0 — every P1–P4 check + the Land Rover emit cell +
  the node determinism test green.
- **Gate:** `pwsh tools/check-all.ps1` → `RESULT: PASS`.

## What is NOT in v1.2 (explicit out-of-scope)

- **W4b — O(n²)→O(n) CCL rewrite** (grid/sweep adjacency). Deferred: guarded by W1; add only when a
  *non-downscalable* asset genuinely needs >8000 rects and profiling confirms segmentation is the bottleneck.
- **Node CLI** (`commander`/`yargs`), root `package.json`, `npm link` / `npx` packaging, `mf.cmd` shim.
- **Asset registry / asset-management layer** — `mf` dispatches; it does not own an asset catalogue, scaffold
  `assets/<name>/`, or manage source/rig provenance.
- **Cross-platform CLI** (macOS/Linux path handling) beyond what pwsh already gives.
- **Auto-rigging research, SAM/VLM segmentation, a Rive/Lottie output target, a web review UI**, or any new
  Output Target — all post-v1.2.
- **Re-running P2 segmentation inside `check-all.ps1` for Land Rover** (it emits from pre-generated
  segmented SVG by design; unchanged).

## Open risks

- **`mf forge` path defaults vs scattered sources.** DevBrain's source PNG now lives under
  `assets/devbrain/poses/`, but its generated rig still lives under `docs/buildable-slice/`; Land Rover
  lives under `spikes/03-second-asset/`. The repo has **no uniform `assets/<name>/` source+rig+out layout**
  yet — only `parts-spec.json` is uniform. `mf` must take source/rig/out as overridable params with
  conventional defaults and **not** assume everything is under `assets/<name>/`, or `forge devbrain`
  breaks. (This is also why a full registry is out of scope.)
- **`-MaxRects` default tuning.** 8000 is a judgement call between "Land Rover (3540) still works" and "catch
  the native-res blow-up early." If a future legitimate asset lands between 3540 and 8000, bump the default or
  pass `-MaxRects` explicitly — the guard is a knob, not a hard wall.
- **Determinism of any elapsed-time print (W1 optional).** Timing output must go to host/stderr only and never
  touch the emitted SVG/HTML, or it breaks the byte-identity gates.
- **`mf emit` and the npm step.** `npm --prefix tools/emit-react-gsap run emit` assumes that package's
  `node_modules` is installed; `mf emit` should fail with a clear message if it is missing rather than a raw
  npm error. (The SVG+CSS half stays dep-free.)
- **Human-pause makes `mf forge` non-linear by design.** `forge` deliberately cannot finish a new asset
  unattended (ADR-0002). That is correct, but means the "single command end-to-end" framing is two commands
  (`forge` … human … `emit`) — documented as such, not a defect.
