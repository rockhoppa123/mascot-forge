## 1. Context

**Pipeline (v1, complete):**
```
PNG →[P1 vectorize]→ flat.svg →[P2 segment + human confirm]→ named parts + pivots →
[author rigged.json]→[P3 emit]→ SVG+CSS & React+GSAP →[P4 orchestrate]→ data-reactive mascot
```

**What Spike 03 proved:** the schema (v2), both emitters, and the runtime carry an unseen asset (Land Rover) with zero edits — but only by *working around* three DevBrain-tuned constants:
1. `segment-parts.ps1` hard-codes the 6-part vocab + geometry rules + viewBox
2. `emit-react-gsap/src/emit.ts` hard-codes `PART_IDS` (the 6 DevBrain ids) for id-namespacing
3. `emit-svg-css.ps1` hard-codes `devbrain-*` output filenames + rejects non-`devbrain-*` files in OutDir

This work removes those work-arounds by making the constants data-driven — behind defaults that reproduce DevBrain behaviour exactly.

**LOCKED — MUST NOT be edited or overwritten:**
- Everything under `docs/buildable-slice/` (the DevBrain goldens)
- `runtime/mascot-state.js` and `tools/emit-react-gsap/src/useMascotState.ts`
- Every existing ADR in `docs/adr/`
- The DevBrain Clean Mascot Source PNG (`assets/devbrain/` or `docs/buildable-slice/`)

## 3. Work items (in order — gate between each)

### W1 — Data-drive the P2 part vocabulary *(most important; do first)*

**File:** `tools/segment-parts.ps1`

Add `-Spec [string]` param (default `$null`):
- When `$null`: run today's heuristic unchanged (DevBrain behaviour preserved)
- When a path is provided: load the JSON from that path, use `parts[].id` + `parts[].hint` instead of the hard-coded vocab list

**`parts-spec.json` schema** — see `docs/v1.1-generalisation-implementation-plan.md` for both the DevBrain and Land Rover examples. The `hint` field maps to existing predicates already in the tool:

| hint | Existing predicate |
|---|---|
| `largest-blob` | rect-group with max total area |
| `below-body-left` | centre.x < body.centre.x AND centre.y > body.bottom |
| `below-body-right` | centre.x ≥ body.centre.x AND centre.y > body.bottom |
| `above-body` | centre.y < body.top |
| `colour-island-upper` | distinct colour region, centre.y in upper half |
| `below-eyes` | centre.y > eyes.centre.y |

No new predicate logic — just dispatch through hint string to the same code paths.

**Create these files:**
- `assets/devbrain/parts-spec.json` (DevBrain, `viewBoxSize: 192`)
- `assets/land-rover/parts-spec.json` (Land Rover, `viewBoxSize: 256`, same 6 hints)

**ADR to write after W1 lands green:**
- File: `docs/adr/0010-part-taxonomy-is-per-asset-data.md`
- Decision: optional `-Spec` param; default `$null` runs existing heuristic; new assets provide their own spec
- Consequences: human-confirm step (ADR-0002) unchanged; DevBrain behaviour preserved by default
