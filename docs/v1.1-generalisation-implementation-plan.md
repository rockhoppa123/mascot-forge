## Work items (priority order — regression-gate after each)

### W1 — Data-drive the P2 part vocabulary *(do first)*

**Now:** `segment-parts.ps1` hard-codes `$vocab` + geometry predicates tuned to the brain.

**Change:** add `-Spec [string]` param (default `$null`). When provided, load a `parts-spec.json` from that path and use its `parts[].id` + `parts[].hint` instead of the hard-coded list. When absent: existing heuristic runs unchanged.

**`parts-spec.json` schema (DevBrain):**
```json
{
  "assetName": "devbrain",
  "viewBoxSize": 192,
  "parts": [
    { "id": "part-body",       "bone": "body",      "hint": "largest-blob" },
    { "id": "part-leg-left",   "bone": "leg_left",  "hint": "below-body-left" },
    { "id": "part-leg-right",  "bone": "leg_right", "hint": "below-body-right" },
    { "id": "part-antenna",    "bone": "antenna",   "hint": "above-body" },
    { "id": "part-eyes",       "bone": "body",      "hint": "colour-island-upper" },
    { "id": "part-moustache",  "bone": "moustache", "hint": "below-eyes" }
  ]
}
```
`viewBoxSize` is used by W3a to carry the correct SVG viewBox. DevBrain spec reproduces today's 6 rules exactly.

**Land Rover `parts-spec.json`** (for W1 second-asset proof):
```json
{
  "assetName": "land-rover",
  "viewBoxSize": 256,
  "parts": [
    { "id": "part-body",       "bone": "body",      "hint": "largest-blob" },
    { "id": "part-leg-left",   "bone": "leg_left",  "hint": "below-body-left" },
    { "id": "part-leg-right",  "bone": "leg_right", "hint": "below-body-right" },
    { "id": "part-antenna",    "bone": "antenna",   "hint": "above-body" },
    { "id": "part-eyes",       "bone": "body",      "hint": "colour-island-upper" },
    { "id": "part-moustache",  "bone": "moustache", "hint": "below-eyes" }
  ]
}
```
Same hint vocabulary; Land Rover anatomy maps to 6 slots (cabin=body, wheels=legs, flag=antenna, headlights=eyes, grille=moustache) — same mapping the spike's `author-manual-part.ps1` performed manually, now expressed as data.

**Hint → predicate mapping** (for reference when editing `segment-parts.ps1`):

| hint | Existing predicate |
|---|---|
| `largest-blob` | rect-group with max total area |
| `below-body-left` | centre.x < body.centre.x AND centre.y > body.bottom |
| `below-body-right` | centre.x ≥ body.centre.x AND centre.y > body.bottom |
| `above-body` | centre.y < body.top |
| `colour-island-upper` | distinct colour region, centre.y in upper half of canvas |
| `below-eyes` | centre.y > eyes.centre.y |

Hints map to existing predicate code paths — zero logic change, just dispatch by hint string.

**ADR-0010:**
- **Title:** Part taxonomy is per-asset data, not a tool constant
- **Status:** Accepted
- **Context:** `segment-parts.ps1` hard-codes DevBrain's 6-part vocabulary + geometry rules. New assets must either fit or the tool must be edited.
- **Decision:** Add optional `-Spec [string]` param pointing to a per-asset `parts-spec.json`. Default `$null` runs existing heuristic unchanged, preserving DevBrain behaviour.
- **Consequences:** New assets provide `assets/<name>/parts-spec.json`. Human-confirm step (ADR-0002) unchanged — spec proposes, human confirms. DevBrain behaviour fully preserved by default.

**Risk:** Hint→predicate routing must reproduce DevBrain CCL output bit-for-bit.  
**Mitigation:** Route through same predicate code paths via hint string — no logic changes. Gate verifies byte-identity.

**Gate (W1):**
```powershell
$tmp = "$env:TEMP\devbrain-seg-w1.svg"
pwsh tools/segment-parts.ps1 -Flat docs/buildable-slice/devbrain-flat.svg -Spec assets/devbrain/parts-spec.json -Out $tmp
git diff --no-index docs/buildable-slice/devbrain-segmented.svg $tmp  # must exit 0
```

```ts
const PART_IDS = ['part-body','part-leg-left','part-leg-right','part-antenna','part-eyes','part-moustache'];
```

### W3 — Carry asset identity through the tools

**W3a — `segment-parts.ps1`:**  
Hard-codes `viewBox="0 0 192 192"` and `data-source=".../devbrain-flat.svg"` in emitted SVG.  
Fix:
- Read `viewBox` from spec's `viewBoxSize` field (if spec present) → `"0 0 $vb $vb"`.
- If no spec: read from flat.svg root attr: `([xml](Get-Content $Flat)).svg.viewBox`.
- Fallback if both absent: compute from `width`/`height` attrs; error if all missing.
- Carry source path from the `-Flat` param instead of hard-coding `devbrain-flat.svg`.

**W3b — `emit-svg-css.ps1`:**  
Add `-AssetName [string]` param (default `"devbrain"`). Apply to:
- Output filenames: `$AssetName-svg-css.generated.*`
- `OutDir` cleanliness check: accept `$AssetName-*` files (read the current check before editing)
- Demo `<h1>` and `<title>` labels

**Contract:** defaults = `"devbrain"` → outputs byte-identical to today.

**Risk (W3a):** flat.svg might lack `viewBox`, `width`, and `height` attributes.  
**Mitigation:** Throw a descriptive error naming the missing attribute — don't silently produce a broken SVG.

**Risk (W3b):** OutDir cleanliness check regex — parameterizing it incorrectly could let cross-asset pollution through.  
**Mitigation:** Read the exact current check string first; replace only the `devbrain` literal with `$AssetName`.

**ADR:** None (pure parameterisation). Note in tool headers.

**Gate (W3):**
```powershell
# DevBrain emit with defaults:
pwsh tools/emit-svg-css.ps1 -AssetName devbrain ...
git diff docs/buildable-slice/devbrain-svg-css.generated.svg  # must show nothing
git diff docs/buildable-slice/devbrain-svg-css.generated.css
git diff docs/buildable-slice/devbrain-svg-css.generated-demo.html
```
